Week 2 assignment: Visitor Counter

There are {{ count }} visits to this page

What this page does

This is a small Python app running behind Nginx on the same virtual machine as Week 1. Nginx takes any request for /viikko2/ and passes it on to the app, which sits in 127.0.0.1:5000 and isn't reachable from the outside. Each time the page loads, the counter goes up by one.

Database

The count lives in an SQLite database file (visitors.db) in the app directory. SQLite doesn't need a separate server process because the whole database is just a file, which keeps things simple and self-contained.

How the counter is stored

Inside the database there's a single-row table called counter with an integer count field. On every request, the app runs an UPDATE ... SET count = count + 1 and then reads the value back to show it. Since the number lives on disk rather than in memory, it survives restarts of both the app and the server.

Restart test

After rebooting the virtual machine, the page came back up normally and the counter carried on from where it left off instead of resetting to zero. That confirms Nginx, the Python app, and the SQLite database all start on their own, and that the visit count sticks around.
